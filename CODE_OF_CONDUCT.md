# Code of Conduct

AuditeDB is a small project with a high-signal engineering culture. Be direct,
technical, and kind.

## Expected Behavior

- Treat other people as collaborators, not obstacles.
- Keep reviews about code, behavior, evidence, and risk.
- Assume good faith until there is evidence otherwise.
- Make disagreement specific: cite files, lines, commands, traces, or protocol
  behavior.
- Prefer small, reviewable changes over large arguments about taste.

## Unacceptable Behavior

- Harassment, threats, sustained personal attacks, or sexualized attention.
- Insults based on identity, background, ability, or experience level.
- Publishing private information without permission.
- Deliberately derailing issues, reviews, or security reports.
- Pressuring the maintainer to merge, release, or disclose before they are
  ready.

## Reporting

Report conduct problems privately through GitHub's "Report a security
vulnerability" form, the same private maintainer-only channel described in
`SECURITY.md`. Conduct reports are not necessarily security issues, but they
need the same private inbox. Do not open a public issue.

Reports should include the link, date, people involved, and a short description
of what happened. The maintainer may remove comments, close threads, block
accounts, or decline contributions to keep the project workable.

## Scope

This code of conduct applies to project spaces: issues, pull requests,
discussions, release threads, and any project-linked communication.

AuditeDB's standard is simple: rigorous work, no cruelty.
